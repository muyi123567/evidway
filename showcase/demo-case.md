# 演示案例（脱敏）

> 这是一个**完全虚构、用于演示**的案例，展示 EvidWay 的完整闭环如何工作。
> 人物、经历与结果均为虚构样例；界面数据经过脱敏处理。

## 案例设定

- 人物：小林（虚构），文科大三学生；
- 困惑：在“考研 / 考公 / 直接就业”之间犹豫，听说“数据运营”不错，但不知道自己是否适合；
- 目标：不要求立刻决定未来，只想先看清下一步并低成本验证。

## 第 1 步：整理“我有什么”

小林输入课程项目、社团经历和一段实习。EvidWay 把这些拆成结构化事实与技能候选，例如：

| 提取内容 | 类型 | 用户确认 |
|---|---|---|
| 校园问卷项目：设计问卷并回收 300+ 样本 | 经历事实 | 已确认 |
| 用表格整理并清洗回收数据 | 技能候选：数据整理 | 已确认 |
| 社团活动文案撰写 | 技能候选：内容表达 | 已确认 |
| “擅长沟通”（无具体事例） | 证据候选 | 待补充 |

没有事例的条目被标为“待补充”，而不是直接写成优势。

## 第 2 步：比较“我可以往哪里走”

围绕“数据运营”，系统给出多条候选路径并列比较，而不是单一答案：

| 路径 | 依据 | 需补足 | 证据等级 |
|---|---|---|---|
| 文科 → 数据运营（实习切入） | 有数据整理先验 + 内容表达 | SQL / 指标体系 | B |
| 文科 → 用户研究 | 问卷设计经历匹配度高 | 研究方法 / 访谈 | B |
| 文科 → 考研（传播学） | 学术兴趣待验证 | 研究计划 | C |

每条路径都标明依据、技能差距和证据等级；“擅长沟通”因待补充而拉低了相关路径的等级。

## 第 3 步：验证“哪条路值得投入”

系统把“我适不适合数据运营”转成一个 7 天最小行动：

- 行动：用公开数据集完成一次完整的清洗 + 一张图表 + 一段 100 字结论；
- 完成标准：产出可展示的工件，而非“看了几篇文章”；
- 检查点：第 3 天记录卡点，第 7 天记录完成度与感受。

## 第 4 步：结果回流

小林完成后回填结果：“清洗比想象中枯燥，但做出图表时有成就感。”
这条结果被写回她的证据账本：

- “数据整理”从技能候选升级为有验证记录的证据；
- 下一次路径比较时，数据运营路径的证据等级与匹配度据此更新；
- 若她发现并不喜欢，系统同样把“不适合”作为有效信号，转向用户研究路径。

## 这个案例想说明什么

- EvidWay 不替小林做决定，而是让她用一周时间获得一个真实信号；
- 建议始终带来源、差距和证据等级，数据不足就明确说不足；
- 用户的真实结果会回到下一次决策，形成可回溯的职业轨迹。
